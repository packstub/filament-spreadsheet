# Changelog

All notable changes to `packstub/filament-spreadsheet` are documented in this file.

## 1.0.0 - Unreleased

First release: spreadsheet-style bulk editing of Eloquent records for Filament 4 (4.13+) and 5.

- `Spreadsheet` definition: `query()` (a resource page inherits the resource's, tenant-scoped), `columns()`, `perPage()`, `searchable()` (a dotted path searches a relation), `defaultSort()`, `filters()` (`Filter::select()`, `Filter::boolean()`, `Filter::dateRange()`, the same class as Kanban and Gantt), `creatable()`, `deletable()`, `saveMode(SaveMode::AllOrNothing|PerRow)`, `readOnly()`, `authorizeUpdate()` / `authorizeCreate()` / `authorizeDelete()` (default: the model's policy when it has the ability), `versionColumn()` (`updated_at` by default, `false` to skip), `beforeSave()`, `afterSave()`, `mutateRowBeforeSave()`, `key()`.
- Columns: `TextColumn` (`maxLength()`, a `max:` rule and the editor's `maxlength`), `NumberColumn` (`integer()`, `decimals()`, `min()`, `max()`; "1 234,50", "1,234.50" and "1.234,50" all read as 1234.5), `BooleanColumn` (1/0, yes/no, true/false, on/off, y/n), `SelectColumn` (`options()` as an array, a closure or a backed enum with `HasLabel`; `relationship()` on a `BelongsTo`, the key stored, the label shown, a paste matched by label or key), `DateColumn` / `DateTimeColumn` (`format()` for display, ISO on the wire, read strictly: a real calendar date in the years 1000–9999), `ComputedColumn` (`state()`, read-only). Common: `label()`, `width()`, `frozen()`, `readOnly(bool|Closure)`, `rules()` (a list, a `required|max:5` string or a closure; a `unique` rule, string or `Rule::unique()`, ignores the record being updated; a cleared cell is written as null unless a `required` rule refuses it), `default()`, `hidden()`, `sortable()`, `placeholder()`.
- Reading: `rows()` answers one page as plain arrays (values after casts, one per visible column; the record's version; the columns locked for that record; whether the policy allows an update or a delete). The request is read strictly: the page number at least 1 and never past what the offset can hold (a crafted one answers an empty page), the page size clamped to `max_per_page`, a sort on a sortable column only, a search escaped for `like` (`!` as the escape character with an explicit `ESCAPE` clause, so `%` finds `100% cotton` on SQLite, MySQL and Postgres alike), filter values the filter offered. A page request that overlaps an earlier one (search while paging) shows the latest answer only, and one still in flight when a save lands is dropped and asked for again after it, so the saved values and versions are never covered by a stale page. An answer that lands while a cell is being typed in (a debounced search, a sort, a page, a `packstub-spreadsheet-refresh`) commits that cell first, as an unsaved change of the page it was on. A page, sort or page-size request that fails or is refused puts the pager, the header arrow and the size select back on what the rows on screen are; the search text and the filters stay as typed. The first page is rendered with the grid once; a later re-render of the component carries no rows and the browser keeps its own.
- Saving: `save(SavePayload)` takes `{changed: {id: {column: value}}, versions: {id: version}, created: {temp: {column: value}}, deleted: [id]}` (every shape checked, nothing else kept), loads the records through `query()`, checks `canUpdate()` / `canCreate()` / `canDelete()` per row, refuses a row whose version changed as a conflict (their value per changed column, the current version), coerces every value by its column, validates with Laravel's validator (every error of a row at once; a new row over every editable column, defaults filled), `forceFill()`s and saves (the columns are the whitelist, `$fillable` is not consulted), and answers with the rows as saved after casts and mutators. Both modes run in one transaction, each row written to a savepoint of it. `AllOrNothing` (default): a single refused row rolls the batch back and every error comes back. `PerRow`: a row the database refuses is rolled back to its savepoint on its own, the other rows kept. In both modes a row the database refuses (a `NOT NULL` column without a `required` rule, a delete blocked by a foreign key) is reported and marked on its row ("could not be saved" / "could not be deleted"), and the rows after it are still checked, the savepoint keeping the transaction usable on Postgres too; any other exception is answered with the generic message. `afterSave()` runs inside the transaction in both modes (an exception rolls everything back); `beforeSave()` before it; both refuse with a `SaveRejected` message. `RowsSaved` (updated, created, deleted keys) fires after the commit, `RowSaveFailed` for each refused row. `max_rows_per_save` caps one batch (the browser knows the cap: a paste stops creating rows there); a row with more cells than twice the sheet's columns is refused with one row message; on an integer key, a key that is not a 64-bit integer is answered as missing without a query. `delete(ids)` deletes through the same checks.
- Pages: `SpreadsheetResourcePage` (access follows the resource policy, rows from `getEloquentQuery()`, the resource's `canEdit()` / `canCreate()` / `canDelete()` per row unless the definition sets its own), `SpreadsheetPage`, the `InteractsWithSpreadsheet` trait for any Livewire component (`spreadsheetRows`, `spreadsheetSave`, `spreadsheetDelete`, all renderless; a refused save answers with its reason, any other exception is reported and answered with a generic message), `SheetAction` for a list page's header (hidden when the sheet page cannot be accessed), `SpreadsheetPlugin`.
- Browser: Tabulator 6 (MIT) bundled behind one `grid.js` adapter, loaded on request only on sheet pages. The grid has its own height (`--ps-sheet-height`: the window below the top bar and the toolbar, or what `getSpreadsheetHeight()` returns), scrolls inside it with the header in place, and renders only the rows around the visible window whatever the page size; Add row scrolls to the new row, typing or F2 on a selected cell that was scrolled away brings it back (also when its row was changed meanwhile by an undo, a redo or a save), and Ctrl+↓ / Ctrl+↑ (with Shift to extend the range) jump down / up the column to the edge of its filled cells, the last / first row of the page in a filled column, with that cell in view (with Alt held as well). Another page, page size, sort, search or filter result opens at its first row; the same page read again (a `packstub-spreadsheet-refresh`, the re-read after a save, Discard) stays where it was scrolled to and keeps the active cell and the selected range (a row that is gone gives its place to the one now there), so the next keystroke goes into the cell the user was on. A sheet rendered while hidden (a tab that is not open, a collapsed section) draws itself when it is shown, and the grid follows a change of its size (the window resized), an open editor kept. Click selects, typing or Enter / F2 / a double-click edits, Enter moves down, Tab moves sideways (without opening the next editor), Escape cancels; inside an open editor ↑ / ↓ commit a text or a number and move one row (the next cell selected, not opened), step the focused part of a date or a date-time and move through a select's options, ← / → and Home / End move the caret, and Page Up / Page Down / Home / End never scroll the grid away from the cell being edited; a date or a date-time can be typed part by part (the editor stays open until Enter, Tab or a click elsewhere, Escape cancels) or picked from the browser's calendar (committed at once); Shift+arrows select ranges; Ctrl+C copies as TSV (labels for selects), Ctrl+V pastes a block at the selection (each cell read by its column; a single cell fills the selection; rows past the last one become new rows when creatable, up to `max_rows_per_save` with the lines left out counted in the toolbar; what cannot be read is painted red at once, in a new row too; the whole paste is one undo step); Delete / Backspace clear and Ctrl+X cuts the cells the user may edit (a locked, read-only or computed cell stays); Ctrl+D fills down; a drag handle fills; Ctrl+Z / Ctrl+Y undo and redo edits, pastes, new rows and deletions; Ctrl+S saves, an open editor's text included (Save is enabled while an editor is open, and only then or with unsaved cells: an editor closed without a change by a click elsewhere, a date picker included, leaves it disabled; a click on Save commits the editor first); Ctrl+Enter adds a row; a double-click, Enter or Space flips a boolean. Ctrl+S works anywhere in the sheet, the other shortcuts while the grid has the focus (the search box and the filters keep their own Ctrl+Z; a toolbar button hands the focus back to the grid, so Ctrl+Y right after a click on Undo redoes; a click into the search box or a filter with an editor open commits the cell and keeps the caret where it was put). Select option labels, the empty-table message and every cell are rendered as text, never as HTML. Changed cells keep an amber corner and stay in the browser across pages, sorting, search and filters ("12 changes on 3 pages"); a save paints errors (red, message on hover) and conflicts (purple, their value next to yours), and editing a refused cell, on a new row too, clears its mark; while a save is in flight the sheet takes no edits (the grid dimmed, keystrokes dropped) so the answer never covers a cell typed meanwhile, and editing resumes when it lands; a save or a page request that fails (connection dropped, 419, an error page from a proxy) releases the sheet on Livewire 3 and 4 alike, with the unsaved cells and the undo history in place and "Could not reach the server. Your changes are still here." shown, so Save retries; `beforeunload` and Livewire's navigate ask before leaving with unsaved changes, text in an open editor included; row numbers, a frozen first column, resizable columns, a context menu on rows, a read-only mode. Keyboard shortcuts configurable (`keybindings`).
- Stylesheet on Filament's palette: dark mode, RTL, the `--ps-sheet-*` variables. Translations: en, ro, ru, de.
- `composer test:js` runs the pure browser parts (TSV, coercion, the buffer, undo, paste, fill-down and clear planning, the save answer) on plain Node; CI pins Node 22 and checks the committed bundle is the one the sources build. The bundles carry Tabulator's copyright and permission notice; `LICENSE.md` has a third-party section.
