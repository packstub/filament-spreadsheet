# Changelog

All notable changes to `packstub/filament-spreadsheet` are documented in this file.

## 1.0.0-beta.1 - 2026-10-28

First release: spreadsheet-style bulk editing of Eloquent records for Filament 4 (4.13+) and 5.

- `Spreadsheet` definition: `query()` (a resource page inherits the resource's, tenant-scoped), `columns()`, `perPage()`, `searchable()` (a dotted path searches a relation), `defaultSort()`, `filters()` (the same `Filter` class as Kanban and Gantt: `Filter::select()`, also `multiple()` and `searchable()` with `preload()`, `getSearchResultsUsing()`, `getOptionLabelUsing()` and `optionsLimit()`; `Filter::boolean()`; `Filter::toggle()`, a checkbox whose `query()` is required; `Filter::dateRange()`; `state()` / `emptyState()` give a value from the URL the shape the browser holds), `filtersLayout()` (`Dropdown`, `Toolbar`, `AboveContent`; the config's `filters_layout` is the default), `creatable()`, `deletable()`, `saveMode(SaveMode::AllOrNothing|PerRow)`, `readOnly()`, `authorizeUpdate()` / `authorizeCreate()` / `authorizeDelete()` (default: the model's policy when it has the ability), `versionColumn()` (`updated_at` by default, `false` to skip), `beforeSave()`, `afterSave()`, `mutateRowBeforeSave()`, `key()`.
- Columns: `TextColumn` (`maxLength()`, a `max:` rule and the editor's `maxlength`), `NumberColumn` (`integer()`, whole numbers up to 2^53 − 1 on both sides, `decimals()`, `min()`, `max()`; "1 234,50", "1,234.50" and "1.234,50" all read as 1234.5, and a lone separator follows the panel's decimal mark, `app()->getLocale()` or the config's `decimal_separator`: "0,125" is 0.125 for a German panel), `BooleanColumn` (1/0, yes/no, true/false, on/off, y/n), `SelectColumn` (`options()` as an array, a closure or a backed enum with `HasLabel`; `relationship()` on a `BelongsTo`, the key stored, the label shown, a paste matched by label or key), `DateColumn` / `DateTimeColumn` (`format()` for display, ISO on the wire, read strictly: a real calendar date in the years 1000–9999), `ComputedColumn` (read-only: `formula()`, a row formula such as `price * stock` or `if(stock < 5, 'Reorder', 'OK')` with arithmetic, comparisons, `&`, `if`, `round`, `min`, `max`, `sum`, `coalesce` and a few more, computed by the server for every row it sends and again in the browser over the unsaved cells (a cell that could not be read is empty to the formula, never its text), so the cell follows an edit, an undo and a paste before Save (the same results on both sides, checked case by case: rounding half away from zero on the number as written, as `decimals()` on a number column does, numbers joined as text the way the browser writes them, text compared by UTF-16 code unit); a formula may read another, and a name that is not a column or a formula that reads itself throws when the sheet is built; `state()`, computed from the record; `decimals()`). Common: `label()`, `width()`, `frozen()`, `readOnly(bool|Closure)`, `rules()` (a list, a `required|max:5` string or a closure; a `unique` rule, string or `Rule::unique()`, ignores the record being updated; a cleared cell is written as null unless a `required` rule refuses it), `validationMessages()` and `validationAttribute()` (per rule and the name in the default messages, as a Filament field's), `default()`, `hidden()`, `sortable()`, `placeholder()`.
- Reading: `rows()` answers one page as plain arrays (values after casts, one per visible column; the record's version; the columns locked for that record; whether the policy allows an update or a delete). The request is read strictly: the page number at least 1 and never past what the offset can hold (a crafted one answers an empty page), the page size clamped to `max_per_page`, a sort on a sortable column only, a search escaped for `like` (`!` as the escape character with an explicit `ESCAPE` clause, so `%` finds `100% cotton` on SQLite, MySQL and Postgres alike), filter values the filter offered. A page request that overlaps an earlier one (search while paging) shows the latest answer only, and one still in flight when a save lands is dropped and asked for again after it, so the saved values and versions are never covered by a stale page. An answer that lands while a cell is being typed in (a debounced search, a sort, a page, a `packstub-spreadsheet-refresh`) commits that cell first, as an unsaved change of the page it was on. A page, sort or page-size request that fails or is refused puts the pager, the header arrow and the size select back on what the rows on screen are; the search text and the filters stay as typed. The first page is rendered with the grid once; a later re-render of the component carries no rows and the browser keeps its own.
- Saving: `save(SavePayload)` takes `{changed: {id: {column: value}}, versions: {id: version}, created: {temp: {column: value}}, deleted: [id]}` (every shape checked, nothing else kept), loads the records through `query()` and locks them until the commit (two saves of one row run one after the other, the second answered with a conflict), checks `canUpdate()` / `canCreate()` / `canDelete()` per row, refuses a row whose version changed as a conflict (their value per changed column, the current version), coerces every value by its column, validates with Laravel's validator (every error of a row at once; a new row over every editable column, defaults filled), `forceFill()`s and saves (the columns are the whitelist, `$fillable` is not consulted), and answers with the rows as saved after casts and mutators, read again through `query()` (its `with()`, `withCount()` and selects included). Both modes run in one transaction, each row written to a savepoint of it. `AllOrNothing` (default; `saveMode()` or the config's `save_mode`, where a value that is no mode throws): a single refused row rolls the batch back and every error comes back. `PerRow`: a row the database refuses is rolled back to its savepoint on its own, the other rows kept. In both modes a row the database refuses (a `NOT NULL` column without a `required` rule, a delete blocked by a foreign key) is reported and marked on its row ("could not be saved" / "could not be deleted"), and the rows after it are still checked, the savepoint keeping the transaction usable on Postgres too; any other exception is answered with the generic message. `afterSave()` runs inside the transaction in both modes (an exception rolls everything back); `beforeSave()` before it; both refuse with a `SaveRejected` message. `RowsSaved` (updated, created, deleted keys) fires after the commit (a listener that throws is reported and the save is still answered as saved: answered as failed, the next Save would create the new rows again), `RowSaveFailed` for each refused row. `max_rows_per_save` caps one batch (the browser knows the cap: a paste stops creating rows there); a row with more cells than twice the sheet's columns is refused with one row message; on an integer key, a key that is not a 64-bit integer is answered as missing without a query. `delete(ids)` deletes through the same checks.
- Pages: `SpreadsheetResourcePage` (access follows the resource policy, rows from `getEloquentQuery()`, the resource's `canEdit()` / `canCreate()` / `canDelete()` per row unless the definition sets its own), `SpreadsheetPage`, the `InteractsWithSpreadsheet` trait for any Livewire component (`spreadsheetRows`, `spreadsheetSave`, `spreadsheetDelete`, all renderless; a refused save answers with its reason, any other exception is reported and answered with a generic message; the `spreadsheetFiltersForm` schema for the filters, so the component implements `HasSchemas`), `SheetAction` for a list page's header (hidden when the sheet page cannot be accessed), `SpreadsheetPlugin`.
- Browser: Tabulator 6 (MIT) bundled behind one `grid.js` adapter, loaded on request only on sheet pages. The grid has its own height (measured by default: the window below the grid's top edge less what follows it on the page, shrunk to the rows of a short page and following the window and the toolbar as they change; a sheet far down a page takes the window below the top bar; or what `getSpreadsheetHeight()` returns, or a length a theme sets on `--ps-sheet-height`), scrolls inside it with the header in place, and renders only the rows around the visible window whatever the page size (never the columns: Tabulator's horizontal virtual renderer now and then left the right-hand cells blank); Add row (the button and Ctrl+Enter alike) scrolls to the new row and puts the active cell on its first editable cell, so what is typed next is the new row's (one undo takes the text back, the next the row, and the active cell then sits on the last row; a new row that is saved keeps the active cell under its real id), typing or F2 on a selected cell that was scrolled away brings it back (also when its row was changed meanwhile by an undo, a redo or a save), and Ctrl+↓ / Ctrl+↑ (with Shift to extend the range) jump down / up the column to the edge of its filled cells, the last / first row of the page in a filled column, with that cell in view (with Alt held as well; a 0 or an unticked box counts as filled). Shift+F10 or the menu key opens the row menu on the active cell's row (scrolled back into view when it was scrolled away), and Escape closes it with the keyboard back on the grid. A boolean cell is named Yes or No for a screen reader. A conflict on a cell whose server value is still the one loaded (another cell of the row changed) says so instead of showing two equal values. Back or Forward with unsaved cells, cancelled, returns to the sheet's own history entry and URL, where the browser has the Navigation API (Chrome, Edge, Safari 26.2 and later, Firefox 147 and later; elsewhere the address bar stays on the other entry, as Livewire leaves it). No history entry is added, and Livewire's back-button cache keeps each page's own markup. Another page, page size, sort, search or filter result opens at its first row; the same page read again (a `packstub-spreadsheet-refresh`, the re-read after a save, Discard) stays where it was scrolled to and keeps the active cell and the selected range (a row that is gone gives its place to the one now there), so the next keystroke goes into the cell the user was on. The columns are measured again once the sheet's stylesheet applies: on a slow first load of the script the first page was rendered before it, every column as wide as the grid and the sheet collapsed to its pinned column. The measuring waits for an open editor to close and keeps the active cell and its row in view; a stylesheet that was already there does not trigger it. A page with no row the user may edit or delete and no row to add wears the read-only pill. A cell focused on a narrow screen scrolls clear of the pinned columns. A sheet rendered while hidden (a tab that is not open, a collapsed section) draws itself when it is shown, and the grid follows a change of its size (the window resized), an open editor kept. Click selects, typing or Enter / F2 / a double-click edits, Enter moves down, Tab moves sideways (without opening the next editor), Escape cancels; inside an open editor ↑ / ↓ commit a text or a number and move one row (the next cell selected, not opened), step the focused part of a date or a date-time and move through a select's options, ← / → and Home / End move the caret, and Page Up / Page Down / Home / End never scroll the grid away from the cell being edited; a date or a date-time can be typed part by part, after Enter / F2 or straight on the selected cell (the first digit opens the editor and lands in its first part; the editor stays open until Enter, Tab or a click elsewhere, Escape cancels; a date left with a part missing keeps the cell's value, every part cleared empties it) or picked from the browser's calendar (committed at once); a select opened with Enter, F2 or a double-click lists every option with its label selected, so the arrows walk the options and a typed letter searches them (typed text confirmed is matched to an option by label or key, case and spaces aside, as a pasted value is (a label first: a label that is also another option's key means the option it labels), and painted red when nothing matches; after ↓ / ↑ moved the highlight, Tab or a click elsewhere take the highlighted option, as Enter does; the list has no empty item: the search field cleared and confirmed empties the cell; an empty list says "No results" in the sheet's language); a cell without an editor opens none: Enter on a computed cell or on a boolean of a read-only sheet does nothing, and neither does a typed character or F2 on a boolean or a computed cell; Shift+arrows select ranges; Alt+← / Alt+→ stay the browser's (Back / Forward): the active cell does not move; Ctrl+C copies as TSV (labels for selects), Ctrl+V pastes a block at the selection (each cell read by its column; a single cell fills the selection; rows past the last one become new rows when creatable, up to `max_rows_per_save` with the lines left out counted in the toolbar, a line with nothing for a new row to take making no row (text only past the last column or on a computed column counts as nothing; a paste of only such lines says so); what cannot be read is painted red at once, in a new row too; the whole paste is one undo step); Delete / Backspace clear and Ctrl+X cuts the cells the user may edit (a locked, read-only or computed cell stays); Ctrl+D fills down; a drag handle fills (what it writes is recorded as changes, as Ctrl+D's are); Ctrl+Z / Ctrl+Y undo and redo edits, pastes, new rows and deletions; Ctrl+S saves, an open editor's text included (Save is enabled while an editor is open, and only then or with unsaved cells: an editor closed without a change by a click elsewhere, a date picker included, leaves it disabled; a click on Save commits the editor first); Ctrl+Enter adds a row (in an open editor it commits the cell first); a double-click, Enter or Space flips a boolean. A key the sheet acts on is the sheet's alone, whatever it is bound to: it never reaches the grid's own key handling as well (Ctrl+Enter opens no editor on the cell it was pressed on), and the characters `!` `"` `#` `$` `%` `&` `'` `(`, whose codes the grid would read as Page Up, Page Down, End, Home and the arrows, are text on every keyboard layout, in an open editor too. Ctrl+S works anywhere in the sheet, the other shortcuts while the grid has the focus (the search box and the filters keep their own Ctrl+Z; a toolbar button hands the focus back to the grid, so Ctrl+Y right after a click on Undo redoes; a click into the search box or a filter with an editor open commits the cell and keeps the caret where it was put; a click on another cell with an editor open leaves the keyboard on the grid, also once that cell's row is scrolled away). Delete rows counts the selected rows the user may delete (a row the policy keeps is not counted, so a viewer is not offered the button; a single active cell is no selection, so the button is not lit on load: select a range or click a row's number). The sheet is a table-style container, the same shell as a Filament table and as Kanban and Gantt (the ring and the rounded corners, the toolbar with the sheet's own controls at the start and the search, the filters and the shortcuts button at the end, the grid without a border of its own, the footer with a line over it); the toolbar, the filters, the badges, the row menu and the dialog are Filament's own components (buttons, icon buttons, the search field a table has, Filament's `Select`, `Toggle` and `DatePicker` form components for the filters, badges, the dropdown, the modal), styled by the panel like any Filament page; the toolbar shows what applies: Save (its count as a badge), Discard, Undo and Redo once something was changed or undone, Delete rows once rows are selected, a "changes" badge only for what the count does not say (changes on other pages, new rows, rows to delete); the filters open from a funnel button with the count of active ones in the button's own badge, stacked under a heading with a Reset link (`filtersLayout()` / the config's `filters_layout`: `dropdown`, `toolbar` inline with each label as its field's prefix, `above` the grid with the heading and Reset; no funnel without filters; the date pickers show the config's `date_format` and start the week on `first_day_of_week`); a "?" button lists every shortcut as bound in a modal; the pager and the status line, with the errors badge beside it, sit in a footer under the grid, as a table's do. A pinned first column (`frozen_first_column`) is off by default: Tabulator warns that a frozen column beside the row numbers can misbehave with range selection, and a pinned header or cell is painted opaque so the columns scrolling under it never show through. Discard and Delete rows ask in Filament's confirmation modal (heading, icon, the focus trapped, Escape and the overlay cancel, translated), never the browser's `confirm()`. The sheet stays invisible until its stylesheet, loaded on request, applies, so the toolbar never shows unstyled for an instant (shown after three seconds regardless). Select option labels, the empty-table message and every cell are rendered as text, never as HTML. Changed cells keep an amber corner and stay in the browser across pages, sorting, search and filters ("12 changes on 3 pages"); a save paints errors (red) and conflicts (purple), the message on hover and, for the active cell, in the live line under the grid (their value next to yours for a conflict), so it is readable from the keyboard and on touch; the toolbar's count of marked cells is a button that moves the active cell to the next one, wrapping; a refused cell carries `aria-invalid`, the sorted header `aria-sort`; the toolbar's tooltips show each shortcut as it is bound, ⌘ on a Mac; editing a refused cell, on a new row too, clears its mark; while a save is in flight the sheet takes no edits (the grid dimmed, keystrokes dropped) so the answer never covers a cell typed meanwhile, and editing resumes when it lands; a save or a page request that fails (connection dropped, 419, an error page from a proxy) releases the sheet on Livewire 3 and 4 alike, with the unsaved cells and the undo history in place and "Could not reach the server. Your changes are still here." shown, so Save retries; `beforeunload` and Livewire's navigate ask before leaving with unsaved changes, text in an open editor included; row numbers, a frozen first column, resizable columns, a context menu on rows, a read-only mode. Keyboard shortcuts configurable (`keybindings`).
- Stylesheet on Filament's palette: dark mode, RTL, the `--ps-sheet-*` variables (the shell's `bg`, `surface`, `border`, `line`, `text`, `muted`, `soft`, `ring`, `radius`, `shadow`, `outline`, `mono` are the same scheme as `--ps-kanban-*` and `--ps-gantt-*`). Translations: en, ro, ru, de.
- CI runs the Pest suite on MySQL 8.4 and PostgreSQL 17 as well as SQLite (`DB_CONNECTION=mysql|pgsql` with the usual `DB_*` variables runs it locally on a real server): row locks, the savepoint per row after a refused statement, the `escape '!'` clause and the `unique` rule are checked where they actually differ.
- The filters are Filament's own form components (`Select`, native for a plain filter, Filament's for a multiple or searchable one, `Toggle`, `DatePicker`), built by `Filter::toFormComponent()` and rendered through the component's `spreadsheetFiltersForm` schema, so they look and behave exactly like a form's and follow every Filament version without copied markup; the component needs `HasSchemas` / `InteractsWithSchemas` (the pages have it). The browser keeps the state as before: a field dispatches its change (`afterStateUpdatedJs`, the `ps-sheet-filter` event), the sheet applies it (`setFilter()`) and writes its state back into the fields without a request (`syncFields()`, `$wire.$set(…, false)`), so a filter change is still no Livewire re-render and Reset clears the fields too. The renderless `spreadsheetFilterOptions`, `spreadsheetFilterOptionLabel` and `spreadsheetFilterOptionLabels` are gone (Filament's select asks its own schema component through `callSchemaComponentMethod`); the funnel dropdown is a panel of fields (`:menu="false"`) and its count sits in the icon button's own badge slot, as the Save and Delete rows counts sit in the button's.
- Caps on filter values: `optionsLimit()` bounds the values a searchable multiple filter accepts (from the browser or the URL) and the label lookups Filament's select makes for them (distinct values, each one not among the options a `getOptionLabelUsing()` call); a value longer than 255 characters is dropped; a search term is read up to 200 characters; `getSearchResultsUsing()` may return a Collection.
- Hardening: a changed row sent without its version while the sheet has a version column is refused as a conflict, not written (the check is the server's, never opt-in from the browser; `versionColumn(false)` still skips it); `TextColumn` without `maxLength()` validates `max:65535`, so no value is unbounded before the database; the grid's HTML escaping also escapes `'`.
- Shell: the container's shadow is a table's (`shadow-sm`) and its text size and line height a table's (`text-sm`), the grid's own sizes unchanged; the filter count sits on the funnel button's top-right corner, as an icon button's own badge does.
- `composer test:js` runs the pure browser parts (TSV, coercion, the buffer, undo, paste, fill-down and clear planning, the save answer) on plain Node; CI pins Node 22 and checks the committed bundle is the one the sources build. The bundles carry Tabulator's copyright and permission notice; `LICENSE.md` has a third-party section.
