# Changelog

All notable changes to `packstub/filament-spreadsheet` are documented in this file.

## 1.0.0 - Unreleased

First release: spreadsheet-style bulk editing of Eloquent records for Filament 4 (4.13+) and 5.

- `Spreadsheet` definition: `query()` (a resource page inherits the resource's, tenant-scoped), `columns()`, `perPage()`, `searchable()` (a dotted path searches a relation), `defaultSort()`, `filters()` (`Filter::select()`, `Filter::boolean()`, `Filter::dateRange()`, the same class as Kanban and Gantt), `creatable()`, `deletable()`, `saveMode(SaveMode::AllOrNothing|PerRow)`, `readOnly()`, `authorizeUpdate()` / `authorizeCreate()` / `authorizeDelete()` (default: the model's policy when it has the ability), `versionColumn()` (`updated_at` by default, `false` to skip), `beforeSave()`, `afterSave()`, `mutateRowBeforeSave()`, `key()`.
- Columns: `TextColumn` (`maxLength()`), `NumberColumn` (`integer()`, `decimals()`, `min()`, `max()`, `step()`; "1 234,50", "1,234.50" and "1.234,50" all read as 1234.5), `BooleanColumn` (1/0, yes/no, true/false, on/off, y/n), `SelectColumn` (`options()` as an array, a closure or a backed enum with `HasLabel`; `relationship()` on a `BelongsTo`, the key stored, the label shown, a paste matched by label or key), `DateColumn` / `DateTimeColumn` (`format()` for display, ISO on the wire, read strictly: a real calendar date in the years 1000–9999), `ComputedColumn` (`state()`, read-only). Common: `label()`, `width()`, `frozen()`, `readOnly(bool|Closure)`, `rules()` (a list, a `required|max:5` string or a closure; a `unique` rule, string or `Rule::unique()`, ignores the record being updated), `default()`, `hidden()`, `sortable()`, `placeholder()`.
- Reading: `rows()` answers one page as plain arrays (values after casts, one per visible column; the record's version; the columns locked for that record; whether the policy allows an update or a delete). The request is read strictly: the page size clamped to `max_per_page`, a sort on a sortable column only, a search escaped for `like` (with an explicit escape character, so `%` finds `100% cotton` on SQLite, MySQL and Postgres alike), filter values the filter offered. The first page is rendered with the grid once; a later re-render of the component carries no rows and the browser keeps its own.
- Saving: `save(SavePayload)` takes `{changed: {id: {column: value}}, versions: {id: version}, created: {temp: {column: value}}, deleted: [id]}` (every shape checked, nothing else kept), loads the records through `query()`, checks `canUpdate()` / `canCreate()` / `canDelete()` per row, refuses a row whose version changed as a conflict (their value per changed column, the current version), coerces every value by its column, validates with Laravel's validator (every error of a row at once; a new row over every editable column, defaults filled), `forceFill()`s and saves (the columns are the whitelist, `$fillable` is not consulted), and answers with the rows as saved after casts and mutators. `AllOrNothing` (default): one transaction, a single refused row rolls the batch back and every error comes back. `PerRow`: each row in its own transaction, a database failure reported and turned into a row error. `afterSave()` runs inside the transaction; `beforeSave()` before it; both refuse with a `SaveRejected` message. `RowsSaved` (updated, created, deleted keys) fires after the commit, `RowSaveFailed` for each refused row. `max_rows_per_save` caps one batch. `delete(ids)` deletes through the same checks.
- Pages: `SpreadsheetResourcePage` (access follows the resource policy, rows from `getEloquentQuery()`, the resource's `canEdit()` / `canCreate()` / `canDelete()` per row unless the definition sets its own), `SpreadsheetPage`, the `InteractsWithSpreadsheet` trait for any Livewire component (`spreadsheetRows`, `spreadsheetSave`, `spreadsheetDelete`, all renderless; a refused save answers with its reason, any other exception is reported and answered with a generic message), `SheetAction` for a list page's header (hidden when the sheet page cannot be accessed), `SpreadsheetPlugin`.
- Browser: Tabulator 6 (MIT) bundled behind one `grid.js` adapter, loaded on request only on sheet pages. Click selects, typing or Enter / F2 / a double-click edits, Enter moves down, Tab moves sideways (without opening the next editor), Escape cancels; Shift+arrows select ranges; Ctrl+C copies as TSV (labels for selects), Ctrl+V pastes a block at the selection (each cell read by its column; a single cell fills the selection; rows past the last one become new rows when creatable; what cannot be read is painted red at once); Delete clears; Ctrl+D fills down; a drag handle fills; Ctrl+Z / Ctrl+Y undo and redo edits, new rows and deletions; Ctrl+S saves; Ctrl+Enter adds a row; a double-click, Enter or Space flips a boolean. Changed cells keep an amber corner and stay in the browser across pages, sorting, search and filters ("12 changes on 3 pages"); a save paints errors (red, message on hover) and conflicts (purple, their value next to yours); `beforeunload` and Livewire's navigate ask before leaving with unsaved changes; row numbers, a frozen first column, resizable columns, a context menu on rows, a read-only mode. Keyboard shortcuts configurable (`keybindings`).
- Stylesheet on Filament's palette: dark mode, RTL, the `--ps-sheet-*` variables. Translations: en, ro, ru, de.
- `composer test:js` runs the pure browser parts (TSV, coercion, the buffer, undo, paste and fill-down planning, the save answer) on plain Node; CI pins Node 22 and checks the committed bundle is the one the sources build.
